# Pull Request Digest for pytorch/torchtitan (20260608-20260615)

本周核心趋势是**Graph Trainer 与 MoE 专家并行从运行可行性全面转向生产级稳定与性能对齐，同时强化学习（RL）训练流得到系统性加固**（90 个 PR，最活跃领域为：1) Graph Trainer/MoE 性能与数值精度，2) RL 训练基础设施，3) SPMD 分片与 MoE 组合，4) 模型与架构支持，5) 硬件/CI 可靠性）。

**1. Graph Trainer 及 MoE 性能、精度与稳定性**
*   [PR#3637](https://github.com/pytorch/torchtitan/pull/3637)、[PR#3590](https://github.com/pytorch/torchtitan/pull/3590)、[PR#3617](https://github.com/pytorch/torchtitan/pull/3617) 等一系列 PR 令 `graph_trainer` 在 chunked-loss 路径上与 eager Trainer 逐位一致，核心改动包括 FSDP 桶负载顺序匹配与 `lm_head` 梯度合并。
*   [PR#3615](https://github.com/pytorch/torchtitan/pull/3615)（含 #3561）及 [PR#3659](https://github.com/pytorch/torchtitan/pull/3659) 引入无同步 MoE 令牌分发器 (`MinimalAsyncEP`) 与偏移感知 SwiGLU 内核，配合 [PR#3616](https://github.com/pytorch/torchtitan/pull/3616) 对 cudagraph 的强制开启，在 H100 上实现完整捕获。
*   [PR#3646](https://github.com/pytorch/torchtitan/pull/3646) 修复全量 inductor 编译时因 ChunkedCELoss 反序列化导致的 OOM；[PR#3596](https://github.com/pytorch/torchtitan/pull/3596) 修复 TP≥2 时 CooR 预编译崩溃。
*   [PR#3640](https://github.com/pytorch/torchtitan/pull/3640)、[PR#3639](https://github.com/pytorch/torchtitan/pull/3639)、[PR#3618](https://github.com/pytorch/torchtitan/pull/3618) 等记录了大量 DeepSeek-V3 16B 在不同配置下的 MFU/内存基准。
*   [PR#3663](https://github.com/pytorch/torchtitan/pull/3663) 移除了 token dispatcher 中从未使用过的 `score_before_experts` 分支与标记。
*   [PR#3649](https://github.com/pytorch/torchtitan/pull/3649)、[PR#3635](https://github.com/pytorch/torchtitan/pull/3635) 等修复了因缺少 DTensor 策略与 nightly 兼容性导致的 CI 红屏。

**2. 强化学习（RL）训练基础设施**
*   [PR#3667](https://github.com/pytorch/torchtitan/pull/3667) 为 RL 训练将 `lm_head` 转为 fp32 精度，以提升 logprob / KL 计算精度，保持生成器-训练器间位一致性。
*   [PR#3593](https://github.com/pytorch/torchtitan/pull/3593)（已合并）以及 [PR#3642](https://github.com/pytorch/torchtitan/pull/3642) 实现了基于 vLLM 的连续批处理生成器及异步 RL 循环，支持多轮 rollout。
*   [PR#3583](https://github.com/pytorch/torchtitan/pull/3583)、[PR#3624](https://github.com/pytorch/torchtitan/pull/3624)、[PR#3625](https://github.com/pytorch/torchtitan/pull/3625) 加入多生成器路由（最少负载 / 轮询）及权重同步。
*   [PR#3602](https://github.com/pytorch/torchtitan/pull/3602) 新增 Search-R1 多轮检索增强 GRPO 任务示例；[PR#3582](https://github.com/pytorch/torchtitan/pull/3582) 引入 AlphabetSort 任务并淘汰 SumDigits。
*   [PR#3575](https://github.com/pytorch/torchtitan/pull/3575) 修复梯度累加错误位置导致的梯度清零；[PR#3629](https://github.com/pytorch/torchtitan/pull/3629) 强制 vLLM 使用训练器 logprob 函数以保持批量不变性。

**3. SPMD 类型系统与 MoE 组合与分片**
*   [PR#3641](https://github.com/pytorch/torchtitan/pull/3641)、[PR#3587](https://github.com/pytorch/torchtitan/pull/3587)、[PR#3643](https://github.com/pytorch/torchtitan/pull/3643) 等引入 `spmd_types` 基础库，提供声明式状态分片与重分布能力。
*   [PR#3655](https://github.com/pytorch/torchtitan/pull/3655)、[PR#3654](https://github.com/pytorch/torchtitan/pull/3654)、[PR#3653](https://github.com/pytorch/torchtitan/pull/3653) 将 Qwen3 MoE 模型接入 SPMD 后端，包括稀疏 SPMD mesh 与分片配置。
*   [PR#3604](https://github.com/pytorch/torchtitan/pull/3604)、[PR#3577](https://github.com/pytorch/torchtitan/pull/3577)（及 #3662）修复 TP 与 SP 同时启用时 `combine()` 的令牌索引错误和形状不匹配。
*   [PR#3631](https://github.com/pytorch/torchtitan/pull/3631) 将 `Embedding` 重命名为 `VocabParallelEmbedding` 以反映其统一处理跨 backend 的 TP 嵌入。

**4. 新模型与架构支持**
*   [PR#3634](https://github.com/pytorch/torchtitan/pull/3634) 新增 DeepSeek V4 模型完整支持（含稀疏 attention、compressor、mHC）。
*   [PR#3666](https://github.com/pytorch/torchtitan/pull/3666) 通过一行修改使 gpt-oss 支持流水线并行（PP）；修复 Qwen3 MoE 丢失 `register_moe_load_balancing_hook` 导致专家偏置未更新的问题。
*   [PR#3603](https://github.com/pytorch/torchtitan/pull/3603) 提供基于 FlexShard 的 DeepSeek V3 eager 训练入口。
*   [PR#3651](https://github.com/pytorch/torchtitan/pull/3651) 加入 Helion 融合 cos/sin RoPE 覆盖，在推理中显著提速。
*   [PR#3573](https://github.com/pytorch/torchtitan/pull/3573) 弃用 llama4，将 `apply_fsdp` 统一至公共文件。

**5. 检查点与状态字典互操作性**
*   [PR#3656](https://github.com/pytorch/torchtitan/pull/3656) 通过 `state_dict` 钩子使 `FusedQKVLinear` 的检查点与普通 `QKVLinear` 兼容。
*   [PR#3638](https://github.com/pytorch/torchtitan/pull/3638) 使 `FusedSwiGLU` 的检查点与 stock `FeedForward` 互操作。
*   [PR#3623](https://github.com/pytorch/torchtitan/pull/3623) 彻底移除对 `torch.distributed` state_dict API 的依赖，使用纯模块级实现，验证了 FSDP/PP 兼容性。
*   [PR#3626](https://github.com/pytorch/torchtitan/pull/3626) 修复 MoE 状态字典转换时的字段名静默丢弃。

**6. 硬件兼容性与 CI 可靠性**
*   [PR#3579](https://github.com/pytorch/torchtitan/pull/3579)、[PR#3597](https://github.com/pytorch/torchtitan/pull/3597) 在 ROCm 上跳过依赖 NVSHMEM 的 HybridEP 和 SymmetricMemory 测试，保持 ROCm 腿绿色。
*   [PR#3588](https://github.com/pytorch/torchtitan/pull/3588)、[PR#3635](https://github.com/pytorch/torchtitan/pull/3635) 适配 CUDA 13 nightly 的 Graph Trainer 兼容性，隔离上游阻塞的 H100 测试。
*   [PR#3660](https://github.com/pytorch/torchtitan/pull/3660) 用 `python -m torch.distributed.run` 替代 `torchrun` 以消除 PATH 依赖。
*   [PR#3657](https://github.com/pytorch/torchtitan/pull/3657) 阻止 cron 工作流在 forks 上运行失败。

**7. 其他关键修复与清理**
*   [PR#3628](https://github.com/pytorch/torchtitan/pull/3628) 将内存快照栈改为纯 Python，并允许配置最大条目数，加速 dump。
*   [PR#3591](https://github.com/pytorch/torchtitan/pull/3591) 改进激活内存日志（显示实际保存量、可读符号形状等）。
*   [PR#3665](https://github.com/pytorch/torchtitan/pull/3665)、[PR#3644](https://github.com/pytorch/torchtitan/pull/3644) 移除对 `fsspec` 的显式依赖及未使用的 `MetricsProcessor.lr_schedulers`。
*   [PR#3661](https://github.com/pytorch/torchtitan/pull/3661)、[PR#3652](https://github.com/pytorch/torchtitan/pull/3652) 修复 `get_train_context` 关键字参数错误及 `no_grad` 路径下多余的 `GradAccumulator` 初始化。
