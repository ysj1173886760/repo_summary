# Pull Request Digest for pytorch/torchtitan (20261102-20261109)

**PR 统计**：共 206 个（已合并 65 · 进行中 48 · 草稿 77 · 已关闭 16），另有 1 个机器人 PR 未计入

## 本周概览
本周 torchtitan 在 RL 训练基础设施、模型并行策略和生成器引擎方面有密集进展。RL 方向重点推进了 SGLang 引擎的全功能支持、流式微批次训练优化以及 vLLM 版本锁定；模型侧新增了 Flash-Next 和 DeepSeek V4.1 的完整训练支持，并修复了 MoE 专家并行中的 batch-invariant 问题；基础设施层面，GraphTrainer 获得了可插拔的 kernel 替换通道和 swarm-based 自动调优能力。

**最活跃领域**：1. RL 训练与生成器引擎；2. 模型支持（Flash-Next、DeepSeek V4.1、Kimi K3）；3. 分布式并行与 MoE；4. GraphTrainer 与编译优化；5. 配置与度量系统重构

## 重点进展
- **SGLang 引擎全功能支持（进行中）**：新增 SGLang 作为 RL 生成器引擎，支持 MoE 专家并行、滑动窗口注意力、GDN 线性注意力、MLA 和 KDA，覆盖 Qwen3 MoE、DeepSeek V3 和 Kimi K3 等模型 [#5812](https://github.com/pytorch/torchtitan/pull/5812) [#5815](https://github.com/pytorch/torchtitan/pull/5815) [#5816](https://github.com/pytorch/torchtitan/pull/5816) [#5817](https://github.com/pytorch/torchtitan/pull/5817) [#5818](https://github.com/pytorch/torchtitan/pull/5818) [#5819](https://github.com/pytorch/torchtitan/pull/5819)
- **流式微批次训练优化（进行中）**：RL 训练器支持每步多次 `forward_backward` 调用，配合 RDMA 预取和统一的 CUDA graph 模式，减少流式微批次场景下的通信等待 [#5761](https://github.com/pytorch/torchtitan/pull/5761) [#5763](https://github.com/pytorch/torchtitan/pull/5763) [#5764](https://github.com/pytorch/torchtitan/pull/5764)
- **MoE batch-invariant 修复**：修复 TP 下 shared/routed expert combine 的 batch-invariant 问题，通过将 routed expert 输出从 all-reduce 改为 all-gather 保证确定性 [#5829](https://github.com/pytorch/torchtitan/pull/5829)
- **Flash-Next 模型完整支持（进行中）**：新增 Qwen3.8 Flash-Next 模型，支持 FSDP + EP、DTensor PLE、TP/SP 和流水线并行，包含 51.2B 参数的 PLE 表分片 [#5782](https://github.com/pytorch/torchtitan/pull/5782) [#5783](https://github.com/pytorch/torchtitan/pull/5783) [#5784](https://github.com/pytorch/torchtitan/pull/5784) [#5785](https://github.com/pytorch/torchtitan/pull/5785)
- **GraphTrainer kernel 替换通道**：新增 `substitute_with_kernels_pass` 和 `autokernel` swarm-based 自动调优技能，支持将 traced 子图替换为手写或 agent 调优的 CuTe DSL kernel [#5840](https://github.com/pytorch/torchtitan/pull/5840) [#5841](https://github.com/pytorch/torchtitan/pull/5841)

## 分领域动态
### RL 训练与生成器引擎
- **vLLM 版本锁定**：RL 环境固定 vLLM 0.33.0 版本，避免 nightly 变更导致 CI 不稳定 [#5958](https://github.com/pytorch/torchtitan/pull/5958) [#5961](https://github.com/pytorch/torchtitan/pull/5961)
- **生成器模型构建解耦**：将引擎无关的模型构建、state dict 加载和 paged attention 从 `vllm/` 移至共享模块，为 SGLang 引擎复用 [#5811](https://github.com/pytorch/torchtitan/pull/5811)
- **vLLM 混合 prefill-decode 优化**：将混合步骤中的单 token decode 行分离为独立 FA4 调用，避免 FA4 选择非最优 kernel [#5941](https://github.com/pytorch/torchtitan/pull/5941)
- **batch-invariant FA4 页面大小修复**：在 SM100/SM103 上强制使用 16-token KV 页面，确保 decode logprobs 与 prefill 一致 [#5870](https://github.com/pytorch/torchtitan/pull/5870)
- **RL loss 温度除法编译优化**：将 `DAPOLoss` 中的温度除法移入编译区域，Qwen3-4B 输出阶段延迟降低 21% [#5921](https://github.com/pytorch/torchtitan/pull/5921)
- **DAPOLoss 全编译（进行中）**：将整个 `DAPOLoss.__call__` 放入编译区域，消除约 80 个 eager kernel，延迟再降 23% [#5923](https://github.com/pytorch/torchtitan/pull/5923)
- **生成器 watermark 默认值**：vLLM 生成器默认 KV 缓存水位线设为 0.1，防止缓存满时新请求导致抢占崩溃 [#5951](https://github.com/pytorch/torchtitan/pull/5951)
- **模型 state dict 增量同步（进行中）**：利用 `StateDictDelta` 仅传输 RL 步骤间变化的参数元素（通常 0.5-2%），减少生成器拉取开销 [#5751](https://github.com/pytorch/torchtitan/pull/5751) [#5872](https://github.com/pytorch/torchtitan/pull/5872)

- **DeepSeek V4 流水线并行**：支持 PP 训练，token ids 到达所有 stage，hash-routed 层可放置于任意 stage [#5767](https://github.com/pytorch/torchtitan/pull/5767)

- **共享专家与 routed combine 重叠（进行中）**：利用 `combine_ready_event` 使共享专家 GEMM 与 routed combine 通信重叠执行 [#5937](https://github.com/pytorch/torchtitan/pull/5937)
