# Pull Request Digest for pytorch/torchtitan (20260615-20260622)

**关键摘要：** 本周最显著的趋势是强化学习（RL）基础设施的深度垂直整合——从多节点分布式生成器到完整的编码智能体沙箱环境，一次性交付了可运行的端到端 RL 工作流。总计 61 个 PR，活跃领域集中在：1. 分布式训练与并行策略；2. 模型组件与精度优化；3. 检查点与容错恢复；4. 开发者体验与 CI/CD；5. 强化学习框架。

## 1. 分布式训练与并行策略
- **[spmd_types] 并行化改造：** 正在大规模迁移至 `spmd_types` 后端。
    - [PR#3690](https://github.com/pytorch/torchtitan/pull/3690)、[PR#3673](https://github.com/pytorch/torchtitan/pull/3673) 相继启用了 GPT-OSS 和 DeepSeek V3 模型。
    - [PR#3726](https://github.com/pytorch/torchtitan/pull/3726) 将 `ChunkedCELoss` 的序列维度 all-gather 重构为基于 `ShardingConfig` 的实现。
    - [PR#3702](https://github.com/pytorch/torchtitan/pull/3702)、[PR#3701](https://github.com/pytorch/torchtitan/pull/3701) **移除了 `loss_parallel` 禁用开关**，统一了 TP 与 LP 的绑定逻辑，并实现了 loss-parallel 的自定义 autograd 接管。
- **[Graph Trainer] 编译与梯度优化：**
    - [PR#3711](https://github.com/pytorch/torchtitan/pull/3711) 在 Graph Trainer 中应用 full inductor 融合区域。
    - [PR#3713](https://github.com/pytorch/torchtitan/pull/3713) 为 `ChunkedCELoss` 实现了梯度通信合并，避免分块反向传播时的多次 `lm_head` 集合通信。
- **[Muon Optimizer] 分布扩展：** [PR#3719](https://github.com/pytorch/torchtitan/pull/3719) 基于 FlexShard 实现了分布式 Muon/MuonClip 优化器，支持专家并行 (EP)。

## 2. 模型组件与精度优化
- **[MoE] 负载均衡与融合：**
    - [PR#3686](https://github.com/pytorch/torchtitan/pull/3686) 修复了混合负载均衡下 `expert_bias` 的更新逻辑。
    - [PR#3712](https://github.com/pytorch/torchtitan/pull/3712) 引入了 `silu_and_mul` 融合内核以加速 SwiGLU。
- **权重初始化修正：** [PR#3722](https://github.com/pytorch/torchtitan/pull/3722) 修复了 Llama3 系列模型中 `trunc_normal_` 因默认边界失效而造成的初始化 bug，并更正了 FFN 深度缩放的归一化目标。
- **融合层维护：**
    - [PR#3728](https://github.com/pytorch/torchtitan/pull/3728) 重构了 `FusedQKVLinear` 的加载/保存钩子以消除重复代码。
    - [PR#3708](https://github.com/pytorch/torchtitan/pull/3708) 修复了因 `x -> x_BLD` 重命名导致的 `GQAttention` 输入重分发（输入仍然保持 `Shard(1)` 而非 `Replicate`）失效。
    - [PR#3681](https://github.com/pytorch/torchtitan/pull/3681) 修复了 SDPA 上下文并行中维度 `Shard` 错位的问题。

## 3. 检查点与容错恢复
- **[Checkpoint] 显式续训与云存储：**
    - [PR#3732](https://github.com/pytorch/torchtitan/pull/3732) **重构了续训逻辑**，将原本容易出错的隐式文件夹检测改为受 `checkpoint.resume` 显式控制的标志。
    - [PR#3730](https://github.com/pytorch/torchtitan/pull/3730) 引入了 `FsspecWriter/FsspecReader`，支持 S3/GCP 等远端存储的高性能检查点存取。
- **[Checkpoint] 缓存一致性与安全：**
    - [PR#3675](https://github.com/pytorch/torchtitan/pull/3675) 通过在原地对钩子产生的张量执行 `copy_`，解决了因 state_dict 存储变化导致异步分页缓存放空的问题。
    - [PR#3724](https://github.com/pytorch/torchtitan/pull/3724) 通过上下文管理器为 `ChunkedCELoss` 添加了异常安全的 FSDP 状态标志恢复。

## 4. 开发者体验与 CI/CD
- **工程效能提升：**
    - [PR#3731](https://github.com/pytorch/torchtitan/pull/3731) 将代码检查工具由 `pre-commit` 切换为 `prek`，环境准备速度提升约 10 倍。
    - [PR#3725](https://github.com/pytorch/torchtitan/pull/3725) 修复了 `ConfigManager.parse_args()` 因捕获导入时快照而无法读取运行时 `sys.argv` 变动的 bug。
- **CI 与测试覆盖率：**
    - [PR#3720](https://github.com/pytorch/torchtitan/pull/3720) 更新 ROCm 集群标签至新的 `amd-do-` 前缀。
    - [PR#3683](https://github.com/pytorch/torchtitan/pull/3683) 新增 `ciflow/graph-trainer` 标签触发器，允许非 Graph Trainer 修改的 PR 主动触发相关测试。
- **代码健康：**
    - [PR#3674](https://github.com/pytorch/torchtitan/pull/3674) 重构了 Activation Checkpointing，引入基于 `Configurable` 的策略类层次结构（`FullAC`, `SelectiveAC` 等）。
    - [PR#3729](https://github.com/pytorch/torchtitan/pull/3729) 修复了 `NoParallel` 钩子在多输出模块上的崩溃。

## 5. 强化学习框架
- **[Coding Agent] 沙箱环境：** [PR#3734](https://github.com/pytorch/torchtitan/pull/3734) 实现了完整的 `swe_r2e` 示例，在 Daytona 沙箱中通过 Claude Code 驱动多轮 SWE 编码智能体进行后训练。
- **[Generator] 多机扩展与稳定性：**
    - [PR#3704](https://github.com/pytorch/torchtitan/pull/3704) 启用了多主机、多生成器 RL（支持 Search-R1, Qwen3-32B），引入 `weight_sync_direct_rdma` 传输选项。
    - [PR#3695](https://github.com/pytorch/torchtitan/pull/3695) 优化了 Controller 与 Trainer 间的数据分发，引入 scatter 模式避免重复发送全量 batch。
    - [PR#3685](https://github.com/pytorch/torchtitan/pull/3685) 修复了 vLLM 在混合 prefill-decode 批次下因全量 CUDA Graph 导致的生成崩溃。
- **[Loss] 强化学习适配：** [PR#3710](https://github.com/pytorch/torchtitan/pull/3710) 将 `ChunkedCELoss` 重构为可插拔 `BaseLoss` 的执行器 `ChunkedLoss`，并成功在其上运行 GRPO。
- **[Model] QKV 与 GPT-OSS：** [PR#3714](https://github.com/pytorch/torchtitan/pull/3714) 为 Qwen3/LLaMA3/GPT-OSS 默认启用了 `fused_qkv`；[PR#3721](https://github.com/pytorch/torchtitan/pull/3721) 启用了 GPT-OSS 作为 RL 的主循环模型。
