# Pull Request Digest for pytorch/torchtitan (20260907-20260914)

**关键要点**：本周 torchtitan 的核心趋势是 **MoE 架构的系统性重构与 Dist-MoE 后端的深度集成，同时训练框架的模块化与分布式正确性修复密集展开**。共 139 个 PR，顶级活跃领域为：1) MoE 与 Dist-MoE 集成，2) 训练引擎与配置重构，3) 流水线并行与 CUDA 图，4) 激活检查点与 RegionAC，5) 上下文并行，6) 分布式正确性修复，7) 硬件后端支持，8) RL 训练，9) 文档与 CI。

---

### 1. MoE 与 Dist-MoE 集成（约 20+ PR）
- **MoE 参数与计算重构**：将 `RoutedExperts` 的 `inner_experts` 替换为显式的 `w13`、`w2`、`activation_fn`、`token_dispatcher`，引入 `GroupedLinear` 作为可复用、无偏置的专家投影层，支持零拷贝视图与 TP/FSDP 分片 [PR#4539](https://github.com/pytorch/torchtitan/pull/4539), [PR#4647](https://github.com/pytorch/torchtitan/pull/4647)。默认启用结构化融合分组专家投影 [PR#4646](https://github.com/pytorch/torchtitan/pull/4646), [PR#4643](https://github.com/pytorch/torchtitan/pull/4643) 和融合 QKV 投影 [PR#4644](https://github.com/pytorch/torchtitan/pull/4644), [PR#4546](https://github.com/pytorch/torchtitan/pull/4546)。
- **Dist-MoE 后端集成**：新增 TorchTitan 适配器，将独立 Dist-MoE 包接入框架，管理 W13/W2 参数、FSDP/优化器、检查点转换等 [PR#4541](https://github.com/pytorch/torchtitan/pull/4541), [PR#4624](https://github.com/pytorch/torchtitan/pull/4624)。提供 DeepSeek V3 的 BF16 和异步 MXFP8 配方 [PR#4542](https://github.com/pytorch/torchtitan/pull/4542), [PR#4625](https://github.com/pytorch/torchtitan/pull/4625)，并编写集成文档 [PR#4543](https://github.com/pytorch/torchtitan/pull/4543), [PR#4626](https://github.com/pytorch/torchtitan/pull/4626)。
- **路由与负载均衡**：为 `TokenChoiceTopKRouter` 添加可重写的 `_compute_scores` 和 `_normalize_topk_scores` 钩子 [PR#4609](https://github.com/pytorch/torchtitan/pull/4609)；支持负载均衡中的 padding mask [PR#4594](https://github.com/pytorch/torchtitan/pull/4594)；实现 Kimi K3 的 Quantile 均衡路由 [PR#4577](https://github.com/pytorch/torchtitan/pull/4577)；将节点限制路由移入 DeepSeek V3 路由器 [PR#4631](https://github.com/pytorch/torchtitan/pull/4631)。
- **其他 MoE 修复**：修复 RL 权重同步中融合 MoE 布局问题 [PR#4583](https://github.com/pytorch/torchtitan/pull/4583)；修复 DeepSeek V4 MTP 的调度器和模块协议初始化 [PR#4515](https://github.com/pytorch/torchtitan/pull/4515)；添加路由输出后处理边界 [PR#4623](https://github.com/pytorch/torchtitan/pull/4623)。

### 2. 训练引擎与配置重构（约 10+ PR）
- **共享训练引擎**：引入可配置的 `TrainingEngine`，将分布式模型生命周期和 per-microbatch 执行逻辑从 Core 和 RL trainer 中抽离，消除重复 [PR#4649](https://github.com/pytorch/torchtitan/pull/4649)。
- **模型配置转换集中化**：将量化、LoRA、batch-invariance、线性类型转换等操作统一到 `torchtitan.config.transform`，提供一致的转换接口 [PR#4648](https://github.com/pytorch/torchtitan/pull/4648)。
- **组件重组**：将 LoRA 和量化移至新位置 [PR#4630](https://github.com/pytorch/torchtitan/pull/4630)；重构日志、profiler、metrics 到 `torchtitan/observability`，模块使用独立命名空间 [PR#4628](https://github.com/pytorch/torchtitan/pull/4628)。
- **配置验证增强**：优化器选择改为基于配置类型而非名称 [PR#4565](https://github.com/pytorch/torchtitan/pull/4565)；拒绝未知的 `pipeline_parallel_schedule` [PR#4564](https://github.com/pytorch/torchtitan/pull/4564) 和 `context_parallel_load_balancer` [PR#4506](https://github.com/pytorch/torchtitan/pull/4506)；异步 TP 无 TP 时发出警告 [PR#4634](https://github.com/pytorch/torchtitan/pull/4634)。
- **废弃清理**：废弃未维护的 `minimal_async_ep` [PR#4627](https://github.com/pytorch/torchtitan/pull/4627)。

### 3. 流水线并行与 CUDA 图支持（约 8 PR）
- **静态流水线执行**：接入 PyTorch 静态 eager 流水线合约，支持规范化的 stage/microbatch 元数据、确定性接收缓冲复用、有向边 P2P 配置 [PR#4540](https://github.com/pytorch/torchtitan/pull/4540), [PR#4619](https://github.com/pytorch/torchtitan/pull/4619)。
- **CUDA 图支持循环流水线**：当使用每物理边独立进程组时，允许循环流水线调度在 CUDA 图重放中运行 [PR#4591](https://github.com/pytorch/torchtitan/pull/4591), [PR#4621](https://github.com/pytorch/torchtitan/pull/4621)。
- **FSDP unshard 前瞻**：通过 `ParallelismConfig` 暴露 FSDP unshard 策略，支持 `default`、`auto` 或显式距离元组 [PR#4592](https://github.com/pytorch/torchtitan/pull/4592), [PR#4620](https://github.com/pytorch/torchtitan/pull/4620)。
- **GraphRunner**：引入 `GraphRunner` 缓存参数枚举等开销，减少梯度累积时的非图运行时开销 [PR#4585](https://github.com/pytorch/torchtitan/pull/4585), [PR#4537](https://github.com/pytorch/torchtitan/pull/4537)；支持图内原位梯度累积以兼容 CUDA 图 [PR#4584](https://github.com/pytorch/torchtitan/pull/4584)。
- **GraphTrainer 提取**：将模型无关的 GraphTrainer 基础设施提取为独立 `graph_trainer` 包 [PR#4517](https://github.com/pytorch/torchtitan/pull/4517)。

### 4. 激活检查点与 RegionAC（约 10 PR）
- **RegionAC 扩展**：新增 feed-forward 区域 [PR#4526](https://github.com/pytorch/torchtitan/pull/4526), [PR#4645](https://github.com/pytorch/torchtitan/pull/4645)、vision transformer 区域 [PR#4611](https://github.com/pytorch/torchtitan/pull/4611)、EP 通信区域 [PR#4612](https://github.com/pytorch/torchtitan/pull/4612)、grouped-expert 区域 [PR#4550](https://github.com/pytorch/torchtitan/pull/4550)。
- **通信完备性**：确保 TP/SP remat 区域在重计算时不重放通信 [PR#4616](https://github.com/pytorch/torchtitan/pull/4616)；在 RegionAC 重放期间保留 SPMD mesh [PR#4614](https://github.com/pytorch/torchtitan/pull/4614)。
- **副作用保留**：激活检查点重放时保存已注册副作用操作的输出，避免二次执行（如分配器、通信状态）[PR#4559](https://github.com/pytorch/torchtitan/pull/4559), [PR#4622](https://github.com/pytorch/torchtitan/pull/4622)。
- **区域自注册与验证**：`Module.register_remat_region` 成为单一真相源，支持发现和拼写检查 [PR#4520](https://github.com/pytorch/torchtitan/pull/4520), [PR#4519](https://github.com/pytorch/torchtitan/pull/4519)；验证配置的模式是否匹配模型区域 [PR#4523](https://github.com/pytorch/torchtitan/pull/4523)。

### 5. 上下文并行（CP）与序列并行（约 6 PR）
- **Kimi K3 CP 支持**：为 KDA/MLA 解码器和多模态输入路径启用上下文并行，KDA 使用 Attention Gym 原生实现，MLA 支持 all-gather K/V CP 或 Ulysses [PR#4639](https://github.com/pytorch/torchtitan/pull/4639)。
- **CP 元数据与输入解耦**：用 `cp_shard_inputs` 替换旧的 `prepare_context_parallel_input`，各 `CPInnerAttention` 后端自行分片元数据 [PR#4617](https://github.com/pytorch/torchtitan/pull/4617)。
- **MTP + CP**：支持 DeepSeek-V3 MTP 的上下文并行，包括 CP+TP 组合，在 CP 分片前对齐 tokens/labels/masks [PR#4544](https://github.com/pytorch/torchtitan/pull/4544)。
- **CP 数值测试修复**：使用非 CP 种子配置进行数值对比测试 [PR#4608](https://github.com/pytorch/torchtitan/pull/4608)。
- **Ulysses-SP 修复**：修复 GraphTrainer eager SAC 下 Ulysses-SP 注意力输出的 A2A 和 WO 边界保存 [PR#4553](https://github.com/pytorch/torchtitan/pull/4553)。
