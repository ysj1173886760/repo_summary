# Pull Request Digest for pytorch/torchtitan (20261109-20261116)

**PR 统计**：共 92 个（已合并 30 · 进行中 11 · 草稿 45 · 已关闭 6）

## 本周概览
本周 torchtitan 在 RL 训练效率、模型并行策略和性能优化方面取得显著进展。RL 模型状态同步通过 RDMA 传输大幅加速，生成器路由和注意力内核修复提升了推理性能。同时，Muse Spark 模型扩展了专家并行选项，多模态架构得到清理，FlexShard 后端和 Flash-Next 模型的支持也在持续推进。

**最活跃领域**：1. RL 训练基础设施；2. 模型支持与架构；3. 并行与分布式策略；4. 性能优化；5. 检查点与存储

## 重点进展
- **RL 模型状态同步加速**：引入 `ModelStateDictTransport` 基于 `torch.distributed._transport`，将 14B 模型同步时间从 10-13 秒降至 0.6-0.9 秒，显著提升大规模 RL 训练效率 [#5996](https://github.com/pytorch/torchtitan/pull/5996) [#5997](https://github.com/pytorch/torchtitan/pull/5997)
- **生成器路由优化**：实现 look-aside 路由，由调用方直接生成，避免通过路由器代理，减少不必要的序列化开销 [#5990](https://github.com/pytorch/torchtitan/pull/5990)
- **SwiGLU 内核编译修复**：移除 `NUM_ROWS` 的 `constexpr` 标记，避免因动态行数导致 Triton 重复编译，特定场景 TPS 提升 8 倍 [#6030](https://github.com/pytorch/torchtitan/pull/6030)
- **多模态模型架构拆分**：将多模态家族拆分为文本 `Decoder` 和 `MultimodalModel` 类，使文本 RL 和纯文本模型更清晰，消除冗余编码器检查 [#6084](https://github.com/pytorch/torchtitan/pull/6084)
- **NUMA 绑定优化**：在 `TrainingEngine` 中绑定训练进程到 GPU 本地 NUMA 节点，提升主机与设备间数据传输带宽 [#5991](https://github.com/pytorch/torchtitan/pull/5991)
