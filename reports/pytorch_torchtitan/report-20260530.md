# Pull Request Digest for pytorch/torchtitan (20260523-20260530)

本周最具影响力的趋势是 MoE 专家并行、Varlen CP 与图训练器的深度融合，推动大规模训练栈向生产级稳定性与自动化性能调优演进。总 PR 数 36。最活跃的领域为：1. MoE 与全 DTensor 并行集成，2. 图训练器编译流程修复，3. CI 基础设施向 OSDC 迁移，4. 自研性能优化（Autoresearch），5. 变长上下文并行（Varlen CP）。

1. MoE 与专家并行（EP）及全 DTensor 支持  
   - [PR #3447](https://github.com/pytorch/torchtitan/pull/3447)：为所有 MoE 模型启用 `--training.full_dtensor`，移除 EP Gate 并使用稀疏 SPMD 网格进行路由专家 FSDP，确保 EP-only 场景下 FSDP2 参数全 DTensor 化。  
   - [PR #3461](https://github.com/pytorch/torchtitan/pull/3461)：为 Qwen3 MoE 增加 TP+EP 配置的确定性损失测试，验证 FSDP+EP 组合的数值一致性。  
   - [PR #3450](https://github.com/pytorch/torchtitan/pull/3450)：在路由器中引入布尔 `routing_map` 替代 `torch.histc` 进行每专家 token 计数，便于分布式下的确定性操作。  
   - [PR #3436](https://github.com/pytorch/torchtitan/pull/3436)：跟进 #3146，完全用 `torch.bincount` 替换 `torch.histc`，使 MoE 路由在无确定性 `_histc` 的后端（如 Intel XPU）运行。  
   - [PR #3425](https://github.com/pytorch/torchtitan/pull/3425)：对 MoE 代码应用 Noam Shazeer 形状后缀约定，提升可读性。  
   - [PR #3433](https://github.com/pytorch/torchtitan/pull/3433)：RFC 设计文档，提议捕获 grouped GEMM 形状及 MoE 运行时指标，为性能分析与负载均衡提供数据基础。

2. 图训练器（graph_trainer）与编译流程修复  
   - [PR #3457](https://github.com/pytorch/torchtitan/pull/3457)：训练时重新应用 `custom_codegen_pass`，避免预编译工件反序列化后退化为 FX 解释执行，节省约 230 ms 延迟。  
   - [PR #3455](https://github.com/pytorch/torchtitan/pull/3455)：修复全 inductor 编译时 CUDAGraph 被静默跳过的 bug，原因是 FlexAttention HOP 在 collapse 前被误判为不兼容。  
   - [PR #3435](https://github.com/pytorch/torchtitan/pull/3435)：消除 `make_fx` 追踪 DTensor 产生的死节点，修复 TP 下因死 SIM 节点索引错误导致的崩溃。  
   - [PR #3429](https://github.com/pytorch/torchtitan/pull/3429)：新增 `“full”` 重计算策略，将所有算子标记为 `PREFER_RECOMPUTE`，在内存受限场景下以少量吞吐换取更大 batch 或序列长度。  
   - [PR #3428](https://github.com/pytorch/torchtitan/pull/3428)：修复 FlexAttention 下因 BlockMask 包含 code 对象而导致的预编译 pickle 失败。  
   - [PR #3432](https://github.com/pytorch/torchtitan/pull/3432)：跳过因上游 PyTorch nightly 回归（`histc` int64、常量折叠、`minimal_fx_tracer`）而失败的测试，恢复 CI 绿色。

3. CI 基础设施迁移至 OSDC  
   - [PR #3464](https://github.com/pytorch/torchtitan/pull/3464)：将 H100 8-GPU 集成测试迁移至 OSDC (ARC) runners，使用 ECR 镜像并包含 ROCm 检查。  
   - [PR #3463](https://github.com/pytorch/torchtitan/pull/3463)：将 Docker 构建流程迁移至 OSDC remote BuildKit，推送至 ECR 并镜像至 GHCR，为后续 GPU 测试奠定基础。  
   - [PR #3444](https://github.com/pytorch/torchtitan/pull/3444)：在 ROCm 8-GPU H100 集成测试中跳过 `fsdp_symm_mem`，因其仅支持 NVIDIA Hopper 架构。

4. 自研性能优化（Autoresearch）  
   - [PR #3442](https://github.com/pytorch/torchtitan/pull/3442)：运行三批次对比实验，在生产图 + 参考实现条件下获得 **+5.21% TPS**，关键收益来自 2 层 FSDP bucket 计划与自动重叠 bucketing。  
   - [PR #3441](https://github.com/pytorch/torchtitan/pull/3441)：仅提供精选优化思路，无参考实现，42 次实验取得 **+64.7% TPS**，核心突破是 CUDA graphs。  
   - [PR #3440](https://github.com/pytorch/torchtitan/pull/3440)：纯自主探索，47 次实验获得 **+44.9% TPS**，发现 `remove_identity_views` 等关键算子融合。

5. 变长注意力与上下文并行（Varlen CP）  
   - [PR #3431](https://github.com/pytorch/torchtitan/pull/3431)：实现面向 Varlen 的 PTRR 负载均衡器，直接从 `cu_seq_q` 估算 Q 块工作量，无需 BlockMask。  
   - [PR #3430](https://github.com/pytorch/torchtitan/pull/3430)：在 Full DTensor 模式下启用 Varlen+CP，利用 DTensor 的 Replicate 放置自动进行 K/V 的 all-gather。  
   - [PR #3424](https://github.com/pytorch/torchtitan/pull/3424)：初步支持 Varlen attention 与 CP，相比 flex+CP+PTRR 有显著性能提升，并移除了相关模型的限制断言。

6. 强化学习与训练器重构  
   - [PR #3453](https://github.com/pytorch/torchtitan/pull/3453)：引入消息级环境协议、Rollout 类型、Rubric 评估和 Renderer，使 GRPO 训练默认支持对话模板。  
   - [PR #3451](https://github.com/pytorch/torchtitan/pull/3451)：将 `grpo.py` 拆分为 `trainer.py` 和 `train.py`，与预训练结构对齐。  
   - [PR #3449](https://github.com/pytorch/torchtitan/pull/3449)：将 Monarch 的 `Future.get()` 替换为 `await fut`，避免事件循环中的同步阻塞。  
   - [PR #3460](https://github.com/pytorch/torchtitan/pull/3460)：改用 `torchmonarch` 的最新稳定版，取消版本固定。

7. 模型组件与 RoPE 优化  
   - [PR #3458](https://github.com/pytorch/torchtitan/pull/3458)：将 RoPE 的 `freqs_cis` 缓存从集中式迁移至每层注意力，并适配 Qwen3-VL 的 MRoPE 动态位置 ID。  
   - [PR #3448](https://github.com/pytorch/torchtitan/pull/3448)：修复 RoPE 重构导致的模型测试失败，包括 DeepSeek V3 MLA 与 Qwen3-VL 的尺寸检查。  
   - [PR #3446](https://github.com/pytorch/torchtitan/pull/3446)：将 Qwen3-VL 视觉编码器转换为基于 Config 的模块，为 parallelize 铺路。  
   - [PR #3445](https://github.com/pytorch/torchtitan/pull/3445)：将 Flux 模块完全转换为基于 Config，无逻辑变更，验证 loss 逐比特一致。

8. 性能与数值修复  
   - [PR #3462](https://github.com/pytorch/torchtitan/pull/3462)：优化 flex flash 的文档掩码效率，利用 packed 特性实现向量化，部分场景速度提升可达 2 倍。  
   - [PR #3454](https://github.com/pytorch/torchtitan/pull/3454)：在 gpt_oss 的 `swiglu` 中用 `addcmul` 避免中间张量分配，减少峰值内存并保持梯度等价。  
   - [PR #3459](https://github.com/pytorch/torchtitan/pull/3459)：EP 中将 `input_splits` 的 D2H 拷贝设为非阻塞，并复用符号整数简化置换逻辑。  
   - [PR #3436](https://github.com/pytorch/torchtitan/pull/3436)（同上）。  
   - [PR #3456](https://github.com/pytorch/torchtitan/pull/3456)：修复 LoRA 冻结时非 Linear 模块仍可训练的问题，引入 `recurse` 遍历和 `FrozenConfig` 包装。  
   - [PR #3426](https://github.com/pytorch/torchtitan/pull/3426)：修复 ForgeEngine 在 `ChunkedCELoss` 下的初始化崩溃。  
   - [PR #3452](https://github.com/pytorch/torchtitan/pull/3452)：移除冗余的 `torch.use_deterministic_algorithms` 调用。

9. 代码风格与可读性  
   - [PR #3443](https://github.com/pytorch/torchtitan/pull/3443)：为注意力模块添加形状后缀注释，明确各后端的布局转换。
