# Pull Request Digest for pytorch/torchtitan (20260914-20260921)

**PR 统计**：共 145 个（已合并 72 · 进行中 19 · 草稿 14 · 已关闭 40）

## 本周概览
本周RL训练与监督训练共享核心引擎，GraphTrainer 执行路径全面统一，MoE 专家投影重构为分组线性，模型配置变换完成中心化。整体向更强的代码复用、更清晰的模块边界和更灵活的分布式执行演进。

**最活跃领域**：1. RL 训练与生成；2. GraphTrainer 与编译；3. MoE 架构；4. 分布式拓扑与并行；5. 配置与模型转换

## 重点进展
- **RL 与监督训练共享核心训练引擎**：提取 `TrainingEngine` 供核心 eager trainer 和 RL trainer 共用，纯重构、无数值变化，减少重复代码并统一训练循环接口。 [#4649](https://github.com/pytorch/torchtitan/pull/4649) [#4773](https://github.com/pytorch/torchtitan/pull/4773)
- **GraphTrainer 统一到管道运行时**：GraphTrainer 现在将 PP=1 也映射为最小管道并重用 `GraphRuntime`，消除原有的专用图运行器，使所有 PP 配置共享同一调度路径。 [#4666](https://github.com/pytorch/torchtitan/pull/4666) [#4766](https://github.com/pytorch/torchtitan/pull/4766)
- **模型配置变换中心化**：将散落在各处的模型变换（量化、LoRA、批不变性等）集中到 `torchtitan.config.transform`，通过统一接口保证行为不变的组合。 [#4648](https://github.com/pytorch/torchtitan/pull/4648)
- **MoE 专家投影重构为分组线性**：引入 `GroupedLinear` 替代不透明的内部专家，采用 `[E, 2, F, D]` 结构化存储，支持零拷贝 GEMM、独立特征维分片及可选的专家输出后处理。 [#4668](https://github.com/pytorch/torchtitan/pull/4668) [#4654](https://github.com/pytorch/torchtitan/pull/4654) [#4667](https://github.com/pytorch/torchtitan/pull/4667)
- **CUDA 图支持循环管道调度**：通过每个有向物理秩边使用独立进程组的策略，允许在 CUDA 图中回放循环管道调度（如 Interleaved1F1B）。 [#4671](https://github.com/pytorch/torchtitan/pull/4671)

## 分领域动态

### RL 训练与生成
- **避免全词表收集进行 TP 策略统计**：logits 和熵保持词表分片计算，大幅减少通信开销。 [#4685](https://github.com/pytorch/torchtitan/pull/4685)
- **GDN 预填充全图捕获**：通过持久化缓冲区管理偏移与缓存槽，用 vLLM 原生 FULL 图捕获 GDN 预填充、混合批次和专用解码，保持数值精确。 [#4738](https://github.com/pytorch/torchtitan/pull/4738)
- **HF 转换后恢复分片布局**：修正 Qwen3.5 等模型在 HF 转换后 DTensor 放置错误，确保检查点适配器重分布后再 `to_local()`。 [#4787](https://github.com/pytorch/torchtitan/pull/4787)
- **ROCm 上跳过不支持的 CUDA 图验证**：导出 `cuda_graphs_supported()` 并在验证器中共享，避免给无捕获能力的设备报错。 [#4790](https://github.com/pytorch/torchtitan/pull/4790)

### GraphTrainer 与编译
- **保留效应于重计算路径**：FullAC 和 SelectiveAC 标记缓存注册操作为 `MUST_SAVE`，防止图重写破坏有序操作语义。 [#4653](https://github.com/pytorch/torchtitan/pull/4653) [#4673](https://github.com/pytorch/torchtitan/pull/4673)
- **WGrad 融合与梯度累积**：分配持久化梯度累加器，允许生产者直接写入，减少 Python 拷贝开销。 [#4768](https://github.com/pytorch/torchtitan/pull/4768)
- **coalesce chunked-loss reduce-scatter（进行中）**：在一个微批次内将多个 ReduceScatter 合并为单次求和后通信，需 opt-in 以平衡数值差异。 [#4734](https://github.com/pytorch/torchtitan/pull/4734)

### MoE 架构
- **结构化分组专家投影设为默认**：采用 `[E,2,F,D]` 布局，通过 `[E,2F,D]` 零拷贝视图调用分组 GEMM，对齐 DistMoE 原生格式。 [#4667](https://github.com/pytorch/torchtitan/pull/4667)
- **专家输出后处理支持**：`RoutedExperts.Config` 可持有可选模块配置，用于 post-expert RMSNorm 等变换，参数所有权归属 FSDP 状态树。 [#4654](https://github.com/pytorch/torchtitan/pull/4654)
- **弃用纯 TP 专家分片**：要求 MoE 专家并行度至少等于密集 TP 度，移除纯 TP 路径，同时保持共享专家 TP 不变。 [#4794](https://github.com/pytorch/torchtitan/pull/4794) [#4798](https://github.com/pytorch/torchtitan/pull/4798)

### 分布式拓扑与并行
- **假和混合拓扑后端**：新增 `comm.backend="fake"` 和 `"real_pp_fake_spmd"`，支持单进程调试多秩逻辑或真管道 + 假 SPMD 组合。 [#4652](https://github.com/pytorch/torchtitan/pull/4652) [#4672](https://github.com/pytorch/torchtitan/pull/4672)
- **MXFP8 线性输出所有权**：预分配形状正确的输出张量并通过 `at::out` 写入，避免下游就地操作额外拷贝。 [#4665](https://github.com/pytorch/torchtitan/pull/4665) [#4674](https://github.com/pytorch/torchtitan/pull/4674)
- **堆叠布局融合前馈投影**：将 W13 从交错行改为 `[2, F, D]`，使各投影连续，防止量化 tile 跨投影污染。 [#4676](https://github.com/pytorch/torchtitan/pull/4676) [#4808](https://github.com/pytorch/torchtitan/pull/4808)
- **重构张量并行投影后端**：将 TP/SP 的重分布职责移入投影边界，明确 `ColumnParallelLinear`/`RowParallelLinear` 的通信角色。 [#4678](https://github.com/pytorch/torchtitan/pull/4678) [#4704](https://github.com/pytorch/torchtitan/pull/4704)

### 配置与模型转换
- **LoRA 迁移到 ModelConfigTransform**：替代旧转换器，解决冻结模块时的继承冲突，并支持未来对 `GroupedLinear` 等非标准模块的 LoRA 应用。 [#4684](https://github.com/pytorch/torchtitan/pull/4684)
- **配置类型遍历简化**：用 `TypeVar` 消除冗余的类型断言和 cast。 [#4759](https://github.com/pytorch/torchtitan/pull/4759)

### 修复与易用性
- **TorchFT 多参数组 FSDP 修复**：修复单个 FSDP 模块包含多个参数组（如 FSDP+EP）时的钩子注册错误。 [#4664](https://github.com/pytorch/torchtitan/pull/4664)
- **CPU 卸载 Muon 流创建修复**：适配 `torch.cpu` 不接受 `device` 参数的 Stream 创建，改为在当前设备流上下文中创建。 [#4750](https://github.com/pytorch/torchtitan/pull/4750)
- **验证步数 `-1` 与 DP>1 冲突检测**：尽早抛出 `ValueError`，防止训练挂起。 [#4807](https://github.com/pytorch/torchtitan/pull/4807)

## 值得关注
- **弃用纯 TP 专家分片**：已有 MoE 配置若未指定 EP 度将报错，必须显式指定 `expert_parallel_degree >= tp_degree`。 [#4794](https://github.com/pytorch/torchtitan/pull/4794) [#4798](https://github.com/pytorch/torchtitan/pull/4798)
- **模型变换接口统一**：旧的分散变换函数已收拢到 `torchtitan.config.transform`，自定义模型需按新接口注册。 [#4648](https://github.com/pytorch/torchtitan/pull/4648)
- **LoRA 应用顺序敏感性**：`ModelConfigTransform` 下 LoRA 必须在 `ContextParallelTransform` 之后运行，否则冻结子类冲突。 [#4684](https://github.com/pytorch/torchtitan/pull/4684)
