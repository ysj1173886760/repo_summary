# Pull Request Digest for pytorch/torchtitan (20261012-20261019)

**PR 统计**：共 179 个（已合并 57 · 进行中 39 · 草稿 76 · 已关闭 7）

## 本周概览
本周重点围绕 RL 训练框架重构、模型架构统一及性能优化展开。RL 侧完成了 Generator 与 Actor 框架的解耦抽象，为多引擎/多框架扩展奠定基础；模型侧统一了 MoE 与 Attention 模块的命名与配置，并引入了 Muse Spark Open 新模型。性能方面，MoE 路由编译、spmd_types 异步通信以及多项内存与计算优化显著提升了训练与推理效率。

**最活跃领域**：1. RL 训练框架与生成器；2. 模型架构与 MoE；3. 性能优化与编译；4. CI/测试与文档；5. 分布式并行与通信

## 重点进展
- **RL 框架核心重构**：将 Generator 拆分为 service、engine loop、dispatcher 和 engine，并引入 `GenerationEngine` 抽象，同时通过 `ActorSystem` 配置化选择 Monarch 等 actor 框架，为接入 vLLM/SGLang 等多引擎及 Ray 等框架铺路 [#5317](https://github.com/pytorch/torchtitan/pull/5317) [#5391](https://github.com/pytorch/torchtitan/pull/5391)
- **Muse Spark Open 模型发布**：引入 816B 参数的 Muse Spark Open 模型，支持 Dist-MoE、BF16 训练及多种并行策略，包含完整的配置、checkpoint 映射与集成测试 [#5420](https://github.com/pytorch/torchtitan/pull/5420) [#5427](https://github.com/pytorch/torchtitan/pull/5427) [#5429](https://github.com/pytorch/torchtitan/pull/5429)
- **MoE 与 Attention 模块统一**：将 MoE、Dist-MoE 和线性层组织为通用模块，统一 `feed_forward` 字段；同时统一 Attention 元数据构建与路由，重命名 DeepSeek MLA 并显式化 inner-attention 配置类型 [#5345](https://github.com/pytorch/torchtitan/pull/5345) [#5335](https://github.com/pytorch/torchtitan/pull/5335)
- **性能优化集合**：编译 MoE 路由与负载均衡求和、spmd_types 模块边界集合异步化、首个 WGRAD 直接在 FP32 下生成、以及 MoE EP 子网格缓存，多项优化累计带来显著的吞吐提升与显存节省 [#5343](https://github.com/pytorch/torchtitan/pull/5343) [#5398](https://github.com/pytorch/torchtitan/pull/5398) [#5399](https://github.com/pytorch/torchtitan/pull/5399) [#5323](https://github.com/pytorch/torchtitan/pull/5323)
- **RL 训练效率与正确性修复**：修复 vLLM 中模型特定 attention 缩放、Dist-MoE 权重加载、MXFP8 子类保留等问题，并默认启用 Monarch RDMA 传输 trainer microbatch，大幅降低通信开销 [#5347](https://github.com/pytorch/torchtitan/pull/5347) [#5340](https://github.com/pytorch/torchtitan/pull/5340) [#5341](https://github.com/pytorch/torchtitan/pull/5341) [#5413](https://github.com/pytorch/torchtitan/pull/5413)

## 分领域动态
### RL 训练框架与生成器
- **Generator 架构拆分**：将 `VLLMGenerator` 拆分为 service、engine loop、dispatcher 和 engine，解耦 vLLM 调用、请求分发与引擎线程循环 [#5317](https://github.com/pytorch/torchtitan/pull/5317)
- **Actor 框架抽象**：引入 `ActorSystem` 配置，将 Monarch 相关逻辑从 controller/trainer 中解耦，支持未来接入 Ray 等其他 actor 框架 [#5391](https://github.com/pytorch/torchtitan/pull/5391)
- **RL 数据发送优化**：Controller 仅向每个 trainer DP rank 发送其所需的数据列，大幅减少内存占用与传输时间 [#5309](https://github.com/pytorch/torchtitan/pull/5309)
- **RL 模型状态字典传输**：统一 RL 中模型状态字典的传输命名与组织方式，按角色分包整理代码 [#5316](https://github.com/pytorch/torchtitan/pull/5316)
- **vLLM 生成器 CUDA Graph 优化**：调整 CUDA Graph 捕获尺寸为 vLLM 默认间距，并增加 prefill 尾部粗粒度尺寸，减少 padding 开销 [#5383](https://github.com/pytorch/torchtitan/pull/5383)
- **Verifiers 集成改进**：升级 `renderers` 版本以支持 Muse Glimmer，并为 Terminal-Bench 任务集注册本地别名，修复环境服务 worker 启动失败问题 [#5375](https://github.com/pytorch/torchtitan/pull/5375) [#5482](https://github.com/pytorch/torchtitan/pull/5482)
- **RL 训练器上下文并行支持（进行中）**：支持在 RL trainer 中启用 context parallelism，正确处理 per-token loss 参数的切分 [#5424](https://github.com/pytorch/torchtitan/pull/5424)

### 性能优化与编译
- **MoE 路由编译**：编译 MoE 路由及其负载均衡求和，减少 kernel launch 开销 [#5343](https://github.com/pytorch/torchtitan/pull/5343)
- **spmd_types 异步通信**：spmd_types 在模块边界集合操作中启用 `async_op`，使通信与计算可重叠 [#5398](https://github.com/pytorch/torchtitan/pull/5398)

- **SwiGLU 区域梯度写入优化**：编译 SwiGLU 区域的 backward，以单次存储写入打包的 gate/up 梯度，减少显存带宽压力 [#5460](https://github.com/pytorch/torchtitan/pull/5460)
- **Muse Spark 性能优化（进行中）**：编译残差流 RMSNorm、attention 内 per-head norm 及 RoPE，并默认启用相关编译区域，提升训练与推理速度 [#5432](https://github.com/pytorch/torchtitan/pull/5432) [#5433](https://github.com/pytorch/torchtitan/pull/5433) [#5434](https://github.com/pytorch/torchtitan/pull/5434) [#5458](https://github.com/pytorch/torchtitan/pull/5458) [#5459](https://github.com/pytorch/torchtitan/pull/5459)
