# Pull Request Digest for pytorch/torchtitan (20260817-20260824)

本周核心趋势是防御性编程全面铺开，通过大量输入验证与配置拒绝消除隐式故障；同时 Checkpoint 系统完成深度抽象重构，`spmd_types` 正式成为默认并行后端，多模态模型获得大量修复与融合。共计 120 个 PR，最活跃的领域依次为：
1. 输入验证与防御性编程
2. Checkpoint 管理层重构
3. 多模态模型支持
4. 分布式后端与并行策略
5. 性能优化与量化
6. 配置与发布流程

## 1. 训练稳定性与输入验证
- [PR#4301] `Raise clear errors when validation yields zero batches or zero valid tokens` — 修复因打包丢弃部分行导致验证循环以无信息 `AssertionError` 退出。
- [PR#4295] `[Bug] Reject negative training.max_norm` — 拒绝负的梯度裁剪值，防止梯度方向反转。
- [PR#4291] `[Bug] Validate activation memory budget` — 拒绝无效的 `activation_memory_budget` (负值、NaN、Inf)。
- [PR#4287] `[Bug] Validate checkpoint load steps` — 拒绝 `load_step < -1` 的非法值。
- [PR#4286] `[Bug] Validate MRoPE dimension contracts` — 验证 MRoPE 片段维度与非负性。
- [PR#4284] `[Bug] Validate TextSequence field lengths` — 确保 `input_ids`、`labels`、`positions` 长度一致。
- [PR#4276] `[Bug] Fail fast on invalid GQA dimensions` — 拒绝隐式的头维度整除失败。
- [PR#4260] `[config] Validate max context length` — 拒绝非正数 `max_context_length`。
- [PR#4258] `[distributed] Validate expert parallel divisibility` — 提前拒绝不能整除的 EP 度数。
- [PR#4233] `Validate profiler schedule configuration` — 提前拒绝 `profile_freq < warmup + active` 的非法调度。
- [PR#4232] `Validate metrics log frequency before scheduling` — 拒绝非正数 `log_freq`。
- [PR#4226] `Stop non-finite steps before optimizer updates` — 每步检测非有限损失，在优化器更新前停止，防止参数损坏。
- [PR#4202] `Add distributed tensor logging` — 添加分布式张量统计记录，用于监控训练健康度。

## 2. Checkpoint 系统重构与增强
- [PR#4187] `Move checkpoint discovery and retention into BaseCheckpointManager` — 将目录扫描与淘汰逻辑上提至基类，通过钩子统一不同后端。
- [PR#4186] `Introduce a storage seam in BaseCheckpointManager` — 引入 `CheckpointStorage` 协议，使基类可表达公共存储策略。
- [PR#4185] / [PR#4184] / [PR#4173] 移除旧版 `components/checkpoint` 与 `checkpoint_utils` 兼容导入，将 `enable` 守卫统一到基类。
- [PR#4188] `Route saves through the torch_checkpointing backend` — 实现 `TorchCheckpointingManager` 保存路径，补全 save/load 闭环。
- [PR#4191] `Route native loads through torch_checkpointing` — 实现原生加载，支持分片与索引 checkpoint，完成 round trip。
- [PR#4190] `Consolidate torch_checkpointing HF final saves` — 原生后端支持合并分片并写出 HF 格式的 `last_save_in_hf`。
- [PR#4277] `[checkpoint] Load Hugging Face checkpoints natively` — 通过临时 `torch_checkpointing` 管理器加载 HF safetensors。
- [PR#4197] `Teach retention about staged and abandoned checkpoints` — 保留策略现在识别临时目录与未完成的 checkpoint，避免误淘汰可用检查点。
- [PR#4279] `[checkpoint] Log native DCP async save durations` — 记录 `dcp_save` future 生命周期。
- [PR#4278] `[checkpoint] Centralize checkpoint trace spans` — 统一 checkpoint 操作的 tracing。
- [PR#4270] `[checkpoint] Wait for async saves during close` — 在 `close()` 中等待异步保存完成，防止资源泄漏。

## 3. 多模态模型支持
- [PR#4195] `[Flux] Normalize validation loss by latent elements` — 修正 Flux 验证损失的归一化方式。
- [PR#4194] `[Forge] Normalize PP loss before backward` — 在流水线反向之前归一化损失，修复梯度不正确问题。
- [PR#4193] `[Flux] Avoid overwriting validation images` — 为 Flux 验证图片添加单调索引，防止覆盖。
- [PR#4244] `[Bug][Muse Glimmer] Fix non-square vision position interpolation` — 修复 `_vision_pos_embed` 中 `grid_sample` 坐标轴顺序错误。
- [PR#4239] `[Bug][Qwen3.5 Video] Fix MRoPE temporal patch positions` — 修复视频 MRoPE 仅生成第一个时间组的错误，现在为每个占位符生成完整 `T x H x W` 网格。
- [PR#4285] `[Bug] Fix video temporal entry capacity counting` — 使用天花板除法而非地板除来计数视频时间条目。
- [PR#4283] `[Bug] Fix Llama 3 fused QKV LoRA targets` — 在 float8 仿真 LoRA 配方中正确瞄准融合的 wqkv。
- [PR#4245] `[Bug][GPT-OSS][spmd_types] Grouped-expert output bias is multiplied by TP degree` — 修复 spmd_types 下未从 DTensor 读取 TP 度数导致的偏置倍乘错误。
- [PR#4262] `[Kimi] Convert the tiktoken vocabulary at download time` — 避开 tiktoken 依赖，修复 Kimi 系列模型的 tokenizer 加载。
- [PR#4261] `Avoid per-item CUDA syncs in multimodal position extraction` — 预先物化元数据列表，去除逐项的 CUDA 同步。
- [PR#4257] `Add SwiGLU fused MXFP8 quant overrides in torchtitan` — 为 SwiGLU MLP 提供融合的 MXFP8 量化路径。

## 4. 分布式后端与并行策略
- [PR#4217] / [PR#4218] 删除 `full_dtensor` SPMD 后端以及旧的 `partial_dtensor` CP 路径，`spmd_types` 成为唯一推荐后端。
- [PR#4235] `[spmd_types] enable transformers modeling backend` — 让 `spmd_types` 支持 transformers 建模后端。
- [PR#4267] `[spmd_types] Preserve requires_grad when distributing parameters` — 修复分布式注册参数时丢失 `requires_grad` 的问题。
- [PR#4282] `Preserve requires_grad in SimpleFSDP parameter registration` — SimpleFSDP 重新注册参数时保留 `requires_grad`。
- [PR#4259] `[optimizer] Restore param-group validation under pipeline parallelism` — 恢复 PP 下的参数组非空验证。
- [PR#4248] `[pipeline] Reject a stage split that renames parameters` — 防止 PP 切分时重命名参数，避免 checkpoint 碰撞。
- [PR#4263] `[DistMuon] turn on pipeline parallelism (again)` — 重新启用 DistMuon 的 PP 支持。
- [PR#4271] `[DistMuon] Drop the foreach-copy compatibility fallback` — 移除过时的兼容回退，直接使用 `_foreach_copy_`。
- [PR#4280] `[DistMuon] Batch compatible local matrix updates` — 将同一层多个形状相同的矩阵合并为一个 Newton-Schulz 调用，减少小 GEMM 开销。
- [PR#4250] `Optimize DistMuon packing copies` — 切片复制合并成批，减少 GPU 启动开销。
- [PR#4252] `[qk_clip] use DTensor dispatch for per-head weight scaling` — 使用 DTensor 视图替代手写的 shard 算术。
- [PR#4182] `Defer chunked loss gradient sync to pipeline schedule` — 将分块损失梯度同步延迟到 PP 调度，减少 reduce-scatter 次数。

## 5. 性能优化与量化
- [PR#4203] `Overhaul MxFP8 support` — 重新设计 MXFP8 线性训练，让 TorchTitan 控制 autograd 与 FSDP 缓存，TorchAO 只提供量化/布局内核。
- [PR#4300] `Fix mfu calculation for muse glimmer and gpt_oss` — 修正滑动窗口注意力的 FLOP 过计数，MFU 不再超过 100%。
- [PR#4298] `[Bug] Use actual step window for end-to-end timing` — 使用真实窗口步数而非 `log_freq` 计算时间，避免 step 1 引起的错误。
- [PR#4201] `Simplify flat packed-document attention mask` — 用 `q_idx - positions[q_idx]` 代替文档 ID 偏移表，提高打包注意力的速度。
- [PR#4171] `Do not read embedding twice to avoid duplicate allgather for SimpleFSDP` — 修复重复读取 embedding 权重导致的重复 all-gather。
