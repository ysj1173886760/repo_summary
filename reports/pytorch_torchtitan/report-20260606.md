# Pull Request Digest for pytorch/torchtitan (20260530-20260606)

**关键要点**：本周 graph_trainer 进入图编译深水区，cudagraph 分段捕获、DCE、AC 兼容层密集迭代；同时 spmd_types 后端快速推进，MoE 模型与 HF 适配器修复全面铺开，RL 训练体系初步成型。**共 93 个 PR**。活跃领域：① graph_trainer 图编译与优化（~25） ② SPMD 类型系统与并行后端（~10） ③ MoE 模型支持与适配（~9） ④ 强化学习训练（~8） ⑤ CI/基础设施（~10）。

---

### 1. Graph Compilation & Optimization（graph_trainer）

- **cudagraph 分段捕获与条件编译**：将整图 cudagraph 拆分为可捕获的干净子图与必须在 eager 执行的区域，使 DeepSeek-v3 MoE 等复杂图能够启用 CUDA 图加速 [PR#3548](https://github.com/pytorch/torchtitan/pull/3548)。引入节点级捕获安全性谓词 `is_cudagraphable` [PR#3533](https://github.com/pytorch/torchtitan/pull/3533)，并为非静态输入添加持久化 buffer 拷贝以兼容跨流内存 [PR#3534](https://github.com/pytorch/torchtitan/pull/3534)（已关闭，合入 #3533）。

- **死代码消除（DCE）**：新增 `eliminate_dead_code_pass`，在内存策略之前清除纯无用的计算节点 [PR#3539](https://github.com/pytorch/torchtitan/pull/3539)（已关闭，合入 #3529）。针对 MoE 追踪产生的 ~97% 死节点（`make_fx` 遗留的 DTensor 元数据传播影子节点），通过 `_remove_dead_empty_strided_chains` 移除，修复了一系列因空张量导致的设备断言失败，并重新激活 14 项先前禁用的测试 [PR#3480](https://github.com/pytorch/torchtitan/pull/3480)。进一步擦除无用的 `_assert_async` 运行时守卫 [PR#3545](https://github.com/pytorch/torchtitan/pull/3545) 和消除冗余的 `lift_fresh_copy` [PR#3544](https://github.com/pytorch/torchtitan/pull/3544)、[PR#3543](https://github.com/pytorch/torchtitan/pull/3543)。

- **激活检查点兼容层**：提供 `--activation_checkpoint.mode` 到 graph_trainer 的映射，`none` 模式跳过内存策略/CPU 卸载/选择性重计算 [PR#3564](https://github.com/pytorch/torchtitan/pull/3564)、[PR#3516](https://github.com/pytorch/torchtitan/pull/3516)。修复 AC 重计算副本共享元数据导致注释错乱的问题 [PR#3530](https://github.com/pytorch/torchtitan/pull/3530)。

- **内存策略与图清理**：强制保存符号形状操作以避免重计算时固定父张量 [PR#3546](https://github.com/pytorch/torchtitan/pull/3546)。移除连续 `aten.t` 转置对（位精准）[PR#3488](https://github.com/pytorch/torchtitan/pull/3488)。修复 gzip 跟踪后处理器和 flaky DSv3 EP 数值测试 [PR#3528](https://github.com/pytorch/torchtitan/pull/3528)。将 `tlparse_log_graph_pass` 移至 `debug_utils` 避免循环导入 [PR#3547](https://github.com/pytorch/torchtitan/pull/3547)。

- **异步 EP 与 MOE 内核**：实现最小化的 cudagraph 友好 MoE 异步专家并行，包括偏移感知的 SwiGLU 内核以跳过填充 [PR#3561](https://github.com/pytorch/torchtitan/pull/3561)。增加 DSv3 16B 的 cudagraph 模式与 HybridEP 配置 [PR#3559](https://github.com/pytorch/torchtitan/pull/3559)。

- **基础修复**：修复 `SimpleFSDP` 在不均匀分片时重包装 `DTensor` 丢失形状的问题 [PR#3549](https://github.com/pytorch/torchtitan/pull/3549)。启用 `full_dtensor` 路径以解耦 `Module.parallelize` 遗留依赖 [PR#3503](https://github.com/pytorch/torchtitan/pull/3503)。

### 2. SPMD Type System & Parallel Backends

- **spmd_types 后端持续推进**：新增 `parallelism.spmd_backend` 配置标志，可选 `default`、`full_dtensor`、`spmd`，并重命名 `full_dtensor` 布尔值为 `spmd_backend` [PR#3540](https://github.com/pytorch/torchtitan/pull/3540)（已关闭）、[PR#3466](https://github.com/pytorch/torchtitan/pull/3466)。实现本地 SPMD 并行化管道 [PR#3470](https://github.com/pytorch/torchtitan/pull/3470) 和运行时网格脚手架 [PR#3469](https://github.com/pytorch/torchtitan/pull/3469)。

- **模型分片配置迁移**：Llama3 解码器分片配置切换为 `spmd.*` 类型 [PR#3471](https://github.com/pytorch/torchtitan/pull/3471)，MoE 模型添加 SPMD 分片配置 [PR#3550](https://github.com/pytorch/torchtitan/pull/3550)。嵌入模块实现自定义词汇并行（本地 SPMD）[PR#3468](https://github.com/pytorch/torchtitan/pull/3468)。

- **损失函数重写**：手动实现 `_LossParallelCrossEntropy` 替代 `loss_parallel()`，支持不均匀分片和 `IGNORE_INDEX`，经位精准验证 [PR#3467](https://github.com/pytorch/torchtitan/pull/3467)（已关闭）。重构 `ChunkedCELoss` 基于 spmd 类型 [PR#3472](https://github.com/pytorch/torchtitan/pull/3472)。损失并行校验放宽以修复前向包装问题 [PR#3560](https://github.com/pytorch/torchtitan/pull/3560)。

- **集成测试**：Llama4 SPMD 类型集成测试启用 [PR#3551](https://github.com/pytorch/torchtitan/pull/3551)（依赖 ghstack），Llama3 后端集成启用 [PR#3475](https://github.com/pytorch/torchtitan/pull/3475)。

### 3. MoE Model Support & Checkpoint Adapters

- **HF 适配器往返修复**：新建参数化 HuggingFace 检查点往返测试 [PR#3553](https://github.com/pytorch/torchtitan/pull/3553)，并修复暴露出的四类模型之间的名称不同步与权重处理错误：Llama4 [PR#3554](https://github.com/pytorch/torchtitan/pull/3554)、GptOss [PR#3555](https://github.com/pytorch/torchtitan/pull/3555)、DeepSeekV3 [PR#3556](https://github.com/pytorch/torchtitan/pull/3556)、Qwen3 [PR#3557](https://github.com/pytorch/torchtitan/pull/3557)。其中关键修复包括 MoE 专家权重名称遵循形状后缀约定（`w1_EFD` 等）、权重绑定路径避免共享别名泄露。

- **MoE 路由简化**：移除 MoE 中 `_scatter` 的本地映射变通方法，利用上游 DTensor sharding 规则直接调用 `scatter_` [PR#3515](https://github.com/pytorch/torchtitan/pull/3515)。

- **新模型与配置**：添加 kimi 2.5 模型 [PR#3532](https://github.com/pytorch/torchtitan/pull/3532)；新增 qwen3_30b_a3b 配置 [PR#3527](https://github.com/pytorch/torchtitan/pull/3527)（已关闭）。

- **graph_trainer + MXFP8 组合性**：为 graph_trainer 的 llama3 和 deepseek 调试模型添加 MXFP8 配置，支持 1 GPU 下的 `ep=1` 路径 [PR#3558](https://github.com/pytorch/torchtitan/pull/3558)。

### 4. Reinforcement Learning (RL) Training

- **RL 集成与修复**：启用 vLLM 生成器与数据并行/专家并行的 RL GRPO 循环，提供 dense DP 和 MoE DP+EP 两种配置示范 [PR#3525](https://github.com/pytorch/torchtitan/pull/3525)。修复 vLLM 1.0 KV-cache 布局变化导致的错误 [PR#3542](https://github.com/pytorch/torchtitan/pull/3542)。修复异步 `_collect_rollouts` 测试 [PR#3518](https://github.com/pytorch/torchtitan/pull/3518) 及 CI 权限问题 [PR#3541](https://github.com/pytorch/torchtitan/pull/3541)。

- **确定性损失守卫**：为 GRPO 训练增加确定性损失比对脚本和 CI 步骤，绑定种子、确定性模式与 TensorBoard 记录 [PR#3474](https://github.com/pytorch/torchtitan/pull/3474)。

- **FlexAttention 区域编译**：在 RL 训练中提供 `regional_inductor_region` 上下文管理器，使 aot_eager 后端下的 FlexAttention 获得 Triton 内核编译，减少 mismatch [PR#3563](https://github.com/pytorch/torchtitan/pull/3563)。

- **分块 CE 损失 RFC**：提出 chunked cross-entropy loss 的 RFC，旨在对齐实现思路 [PR#3477](https://github.com/pytorch/torchtitan/pull/3477)。

- **vLLM 内核测试**：尝试使用 vLLM 的 Triton 内核计算 logprobs 以调试微小差异 [PR#3500](https://github.com/pytorch/torchtitan/pull/3500)。

---

### 5. CPU Offloading & NUMA

- **CPU 激活卸载增强**：支持视图链（transpose、reshape）的卸载，在反向重加载后重放视图算子 [PR#3522](https://github.com/pytorch/torchtitan/pull/3522)、[PR#3521](https://github.com/pytorch/torchtitan/pull/3521)、[PR#3513](https://github.com/pytorch/torchtitan/pull/3513)。修复 `wait_tensor` 在非 Tensor 消费者（如 `sort` 生成 tuple）时参数错误 [PR#3523](https://github.com/pytorch/torchtitan/pull/3523)、[PR#3520](https://github.com/pytorch/torchtitan/pull/3520)。

- **NUMA 绑定**：CUDA 硬件上通过 `torch.numa.binding` 将 worker 绑定到对应 GPU 的 NUMA 节点，内存带宽提升 ~3 倍（~330 GB/s vs ~115 GB/s）[PR#3519](https://github.com/pytorch/torchtitan/pull/3519)（已关闭）。默认启用 NUMA 绑定并修复 Blackwell 硬件上的 `torchrun` 参数 [PR#3489](https://github.com/pytorch/torchtitan/pull/3489)。
