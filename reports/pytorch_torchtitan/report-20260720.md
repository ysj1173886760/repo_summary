# Pull Request Digest for pytorch/torchtitan (20260713-20260720)

**关键摘要**：本周最显著的趋势是 `graph_trainer` 对先进内存优化策略（AC、CPU offload、策略自动化）的密集投入，同时 RL 实验和模型配置生态也在持续扩张。本周共分析 40 个 PR，最活跃的领域为：1) `graph_trainer` 内存/编译优化, 2) 实验性 RL 特性与修复, 3) 新模型配置支持, 4) `spmd_types` 类型系统完善, 5) 硬件后端与分布式通信覆盖。

---

### 一、 核心特性与优化 (`graph_trainer`, 编译)

*   **自动化内存策略 (联合 AC 与 CPU Offload)**
    *   [PR#3943](https://github.com/pytorch/torchtitan/pull/3943) (closed 前身为 [PR#3942](https://github.com/pytorch/torchtitan/pull/3942)) 引入 `--compile.memory_policy auto_perf_maxing`，在 joint graph 上自动按张量粒度决定**保留/重计算/CPU offload**，以达到用户设定的内存预算并最小化运行时开销。
    *   [PR#3949](https://github.com/pytorch/torchtitan/pull/3949) 增加了 `occurrence-aware` 重计算策略封装，允许基于操作符目标、模块 FQN 和出现次数来识别并选择性处理重复节点，增强了重计算策略的灵活性。
    *   [PR#3922](https://github.com/pytorch/torchtitan/pull/3922) 修复了选择性激活重计算在提升 `reload` 节点时破坏 H2D/计算重叠的问题，通过分离 `reload` 依赖项和 `bwd_wait` 来恢复预取窗口。

*   **子图与编译器集成**
    *   [PR#3941](https://github.com/pytorch/torchtitan/pull/3941) 明确了 `GraphTrainer` 基于显式子图注释的 API，去除了遗留兼容代码，并通过 AOTAutograd 的 HOP pass 和完整的 `Inductor` 区域路径来处理带 bw+grad-accum 缝合的整图。

### 二、 实验与模型支持 (RL, 新模型, MoE)

*   **RL 训练框架 (批处理与调度)**
    *   [PR#3938](https://github.com/pytorch/torchtitan/pull/3938) 将 RL 批处理器替换为**成本感知的贪心打包器**，按序列长度平方和为成本，以最长优先策略填充，并支持溢出时刷新。
    *   [PR#3927](https://github.com/pytorch/torchtitan/pull/3927) 为 `RolloutGroupWorkBuffer` 增加了**窗口 FIFO 调度**，允许批处理器在落后 worker 完成前提前返回，牺牲部分分布一致性以换取吞吐量。
    *   [PR#3926](https://github.com/pytorch/torchtitan/pull/3926) 和 [PR#3925](https://github.com/pytorch/torchtitan/pull/3925) 进行了 RL 实验代码的重命名以澄清术语，并实现了每次运行使用独立 dump 目录以避免 checkpoint 冲突。

*   **新模型配置与调试支持**
    *   新增若干模型配置：`Qwen3-4B-Base` [PR#3947](https://github.com/pytorch/torchtitan/pull/3947)，`deepseek-v3-16b-chat` [PR#3946](https://github.com/pytorch/torchtitan/pull/3946)，以及 `deepseek` + `mxfp8` 的 debug 配置 [PR#3934](https://github.com/pytorch/torchtitan/pull/3934)。
    *   [PR#3935](https://github.com/pytorch/torchtitan/pull/3935) 修复了 `mxfp8` MoE 在 `ep=1` 时不工作的问题，便于在单 GPU 上调试小模型。
    *   [PR#3916](https://github.com/pytorch/torchtitan/pull/3916) 为 `MinimalAsyncEP` 添加了负载均衡的容量调整，在开启 `debug.moe_force_load_balance` 时能使用更小的对称接收缓冲区。
    *   [PR#3914](https://github.com/pytorch/torchtitan/pull/3914) 增加了一个可选的 **NVFP4 训练 override**，在 `Linear` 层中将激活、权重和梯度量化为 NVFP4 格式，并支持序列并行 TP。

### 三、 核心组件与类型系统 (`spmd_types`, `DTensor`)

*   **SPMD 类型系统演进**
    *   [PR#3924](https://github.com/pytorch/torchtitan/pull/3924) 和 [PR#3937](https://github.com/pytorch/torchtitan/pull/3937) 均移除了硬编码的 `spmd_types`，改为从输入动态推导 `FlexAttention` 和 `VarlenAttention` 的输出 SPMD 类型，消除了对 DP/TP/CP 轴的假设。
    *   [PR#3913](https://github.com/pytorch/torchtitan/pull/3913) 修复了在 partial mesh 上将 `spmd` 翻译为 `DTensor` 时的失败问题，确保只在当前 mesh 存在的轴上做转换。
    *   [PR#3920](https://github.com/pytorch/torchtitan/pull/3920) 增加了对嵌套重分布规格的 override 遍历支持，并允许在满足条件时将 TP `Partial -> Replicate` 操作替换为基于 `symm_mem` 的 all-reduce 实现。
    *   [PR#3928](https://github.com/pytorch/torchtitan/pull/3928) 记录了严格 SPMD 初始化契约并新增了 `DTensor` **状态化 RNG 初始化 parity 测试**，比对分布式与单设备初始化的一致性。

*   **通用模块重构**
    *   [PR#3923](https://github.com/pytorch/torchtitan/pull/3923) 将 `Linear` 和 `ScaledBiasRowwiseLinear` 移动到 `torchtitan/models/common/linear.py` 以提高代码复用性。

### 四、 硬件后端与分布式通信

*   **浮点精度与硬件限制**
    *   [PR#3945](https://github.com/pytorch/torchtitan/pull/3945) 为 `deepseek_v3_671b` 配置的 float8 转换器添加了硬件能力门控，仅在 SM89+ 或 MI300+ 上启用，防止在不支持的后端（如 Intel XPU, A100）上报错。
*   **后端图捕获支持**
    *   [PR#3931](https://github.com/pytorch/torchtitan/pull/3931) 为 `graph_trainer` 增加了 XPU 图支持，同时保持现有 CUDA 行为不变，并将集成测试从 CUDA 特定描述更新为通用的 `graph_capture` 测试。
*   **上下文并行新原语**
    *   [PR#3929](https://github.com/pytorch/torchtitan/pull/3929) 为 Qwen3.5/3.6 的混合解码器架构新增了**序列/头交换**和**邻居 halo** 通信原语，以支持包含全注意力和状态空间层模型的上下文并行。

### 五、 测试、CI 与依赖维护

*   **测试稳定性与 CI 修复**
    *   [PR#3930](https://github.com/pytorch/torchtitan/pull/3930) 修复了因 vLLM 上游接口变更导致的 RL CI 失败。
    *   [PR#3921](https://github.com/pytorch/torchtitan/pull/3921) 系统性地跳过了因缺少 CUDA 设备、Flash Attention 3 或 `torchcomms` 等依赖而无法运行的测试用例。
    *   [PR#3912](https://github.com/pytorch/torchtitan/pull/3912) 和 [PR#3915](https://github.com/pytorch/torchtitan/pull/3915) 分别修复了 varlen CI 测试挂起问题，并通过 bisect 定位 RL CI 挂起的根源。
    *   [PR#3908](https://github.com/pytorch/torchtitan/pull/3908) 修复了因 `datasets` 库版本过高导致的数据加载器在二次恢复时重启的问题。
*   **依赖更新与代码健康**
    *   [PR#3909](https://github.com/pytorch/torchtitan/pull/3909) 自动将 `transformers` 从 4.57.1 升级到 5.5.0。
    *   [PR#3918](https://github.com/pytorch/torchtitan/pull/3918) 澄清了 MoE 调度器中的变量名并添加了注释。
