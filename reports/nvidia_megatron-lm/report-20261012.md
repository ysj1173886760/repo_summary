# Pull Request Digest for nvidia/megatron-lm (20261005-20261012)

**PR 统计**：共 223 个（已合并 34 · 进行中 90 · 草稿 87 · 已关闭 12）

## 本周概览
本周合入集中于大规模训练与推理的性能和正确性修复：CUDA graph 全迭代捕获、GTP 梯度流同步、MoE 通信/算子带宽优化均有落地。同时，系统性的 `ProcessGroupCollection` 隔离重构开始大面积推进，旨在消除对全局 `parallel_state` 的隐式依赖，后续兼容性值得关注。

**最活跃领域**：1. 进程组隔离与分布式基础设施；2. 推理与服务优化；3. MoE 与性能优化；4. CI/构建与工程效率；5. 训练与优化器

## 重点进展
- **CUDA graph 全迭代捕获修复**：修复 PyTorch >=2.14 下 PP>1 且 `cuda_graph_impl="full_iteration"` 时的 `cudaErrorCapturedEvent`，改为在捕获开始时为每个 CUDA generator 创建 RNG capture state。 [#7885](https://github.com/nvidia/megatron-lm/pull/7885)
- **MoE 分页 stash 与 residual 融合**：`moe_paged_stash_copy_block_size` / `max_blocks` 可调，使 VR200 上 fp8 stash 带宽从约 3.8 TB/s 提升至接近 `copy_` 水平；MoE combine 后 shared-expert 与 residual add 融合为单个 Triton kernel，读数一次且输出位一致。 [#7897](https://github.com/nvidia/megatron-lm/pull/7897) [#7943](https://github.com/nvidia/megatron-lm/pull/7943)
- **优化器精度与参数路径**：允许 FP8 compute 但 BF16 params (`fp8_param_gather=False`) 使用 precision-aware optimizer，避免额外 FP32 masters；同时强制 `--fp4-param-gather` 必须搭配分布式优化器。 [#7915](https://github.com/nvidia/megatron-lm/pull/7915) [#8009](https://github.com/nvidia/megatron-lm/pull/8009)
- **GTP wgrad scratch 跨流同步**：为回收的 wgrad scratch buffer 携带 completion events，取出时在新 writer stream 上等待，修复 MTP backward 暴露的 eager GTP 重用竞争。 [#7927](https://github.com/nvidia/megatron-lm/pull/7927)
- **推理输出与 MLA 性能**：detokenize 按生成 EOS 集合统一剥离尾部 token；新增 `include_stop_str_in_output` 支持工具调用 stop string；MLA 下投影切片改用 2D-tiled Triton copy。 [#7938](https://github.com/nvidia/megatron-lm/pull/7938) [#7933](https://github.com/nvidia/megatron-lm/pull/7933) [#7957](https://github.com/nvidia/megatron-lm/pull/7957)

## 分领域动态

### 推理与服务
- **`DynamicInferenceEngine` 拆分为 mixin 模块（进行中）**：将 `dynamic_engine.py` 从约 5000 行降至 1000 行，按逻辑重新组织，仅 shutdown 一行逻辑变化。 [#7886](https://github.com/nvidia/megatron-lm/pull/7886)
- **修复 refit 后 prefix-cache 重新加盐缺失**：权重 epoch salt 在 `add_request` 时固定，导致旧权重计算的 prefix cache 块在 refit 后仍可被匹配。 [#7891](https://github.com/nvidia/megatron-lm/pull/7891)
- **移除推理 `disable_ep_consensus` flag（进行中）**：删除 `--inference-disable-ep-consensus` 及其跳过 EP-group consensus 的分支，统一走 throttled consensus 路径。 [#7926](https://github.com/nvidia/megatron-lm/pull/7926)
- **将 VLM inference server 从 core 中分离**：降低核心推理与视觉服务耦合。 [#7949](https://github.com/nvidia/megatron-lm/pull/7949)
- **EP dummy MTP forwards 未经过 inference context（进行中）**：修复 speculative decoding 在 head_dim 256 下无 attention backend 可用的问题。 [#8040](https://github.com/nvidia/megatron-lm/pull/8040)
- **无训练 args 的 Megatron-Bridge VLM checkpoint 服务（进行中）**：当 checkpoints 无 saved args 且显式传入 `--vision-model-type` 时，从 CLI 构建 `LLaVAModel`。 [#8041](https://github.com/nvidia/megatron-lm/pull/8041)

### FSDP / MFSDP
- **集中化 `FsdpContext` 构造**：通过 `**kwargs` 前向构造参数，将设备默认与 CUDA 校验移入构造函数，新增选项只需改一处。 [#7895](https://github.com/nvidia/megatron-lm/pull/7895)
- **`GlobalLayout` API 扩展**：新增 rank/tensor range API 并接受可迭代输入，`DBuffer` 可直接推导本地视图。 [#7963](https://github.com/nvidia/megatron-lm/pull/7963) [#7993](https://github.com/nvidia/megatron-lm/pull/7993)
- **按计算阶段 gather MXFP8 权重平面（进行中）**：MFSDP v2 前向仅 gather rowwise、backward 数据梯度 GEMM 仅 gather columnwise，约减半 all-gather 字节。 [#7907](https://github.com/nvidia/megatron-lm/pull/7907)
- **meta-device init 下 tied embedding 同步修复（进行中）**：修复 FSDP + PP/MTP 场景因 all-reduce 跳过导致 embedding 拷贝不一致的问题。 [#8010](https://github.com/nvidia/megatron-lm/pull/8010)
- **MFSDP v2 非 padded uneven shards（进行中）**：BlockAtomic 布局可选关闭 padding，缓解大 DP 下超过 80% 的 padding 开销。 [#8116](https://github.com/nvidia/megatron-lm/pull/8116)

### MoE 与性能

## 值得关注
- **破坏性变更**：[#7926](https://github.com/nvidia/megatron-lm/pull/7926) 拟移除 `--inference-disable-ep-consensus`；[#8015](https://github.com/nvidia/megatron-lm/pull/8015) 拟移除 `ModelParallelConfig.cpu_offloading_weights`（TE 2.10+ 已无作用）；[#8005](https://github.com/nvidia/megatron-lm/pull/8005) 已回滚依赖更新恢复旧约束。
- **进程组隔离重构范围极大**：从 [#8020](https://github.com/nvidia/megatron-lm/pull/8020) 到 [#8060](https://github.com/nvidia/megatron-lm/pull/8060) 系列约 30 个 draft/open PR 将大部分模块从全局 `parallel_state` 迁移到显式 `ProcessGroupCollection`，合并后可能影响外部依赖全局进程组的集成代码。
- **大规模重写风险**：[#7886](https://github.com/nvidia/megatron-lm/pull/7886) 将 `DynamicInferenceEngine` 拆分 mixin，虽声称仅 shutdown 一行逻辑变化，但属于高复杂度重构。
