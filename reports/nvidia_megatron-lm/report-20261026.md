# Pull Request Digest for nvidia/megatron-lm (20261019-20261026)

**PR 统计**：共 141 个（已合并 26 · 进行中 58 · 草稿 53 · 已关闭 4）

## 本周概览
本周重点围绕 MoE 通信重叠与推理延迟优化展开，同时混合模型残差合约得到重构，训练稳定性与配置管理也有重要修复。多个 PR 聚焦于将 CUDA 图能力扩展到专家并行和序列打包场景，以提升大规模训练与推理效率。

**最活跃领域**：1. MoE 与专家并行；2. 推理优化；3. 混合模型与 Mamba；4. FSDP；5. 训练与数据

## 重点进展
- **重构 `CheckpointWithoutOutput` 内部架构**：重新设计输出丢弃重计算的内部实现，支持无 autograd 图时的普通调用，提升代码清晰度 [#8334](https://github.com/nvidia/megatron-lm/pull/8334)
- **GTP 下保持独立专家预取链**：将分组专家 FC1/FC2 预取链扩展到全迭代和局部 CUDA 图，增大通信重叠窗口，提升 MoE 训练吞吐 [#8345](https://github.com/nvidia/megatron-lm/pull/8345)
- **推理中 MoE 工作按活跃行限制**：修复批量不变推理中 MoE 计算量与最大令牌数成比例的问题，解码延迟大幅降低（如 76ms→12ms） [#8385](https://github.com/nvidia/megatron-lm/pull/8385)
- **共享 Mamba 分支执行**：引入 `ResidualBranchInput` 统一 Mamba 与宽残差的状态传递，简化混合模型逻辑并减少冗余 [#8344](https://github.com/nvidia/megatron-lm/pull/8344)
- **修复序列打包调度器在中间流水线阶段的崩溃**：解决打包数据在 ≥3 个流水线阶段且无 VPP 时的 `AssertionError`，保障训练稳定性 [#8378](https://github.com/nvidia/megatron-lm/pull/8378)
