# Pull Request Digest for nvidia/megatron-lm (20261109-20261116)

**PR 统计**：共 252 个（已合并 18 · 进行中 68 · 草稿 115 · 已关闭 51）

## 本周概览
本周主线集中在三个方面：动态推理状态机与 MTP/KV 一致性的批量修复（多为进行中的 production fix），GTP 权重 checkpoint 正确性与 MFSDP 运行时策略的演进，以及训练启动校验的大量增强（多由 community-request 驱动的早期失败检查）。此外，稀疏注意力/SSM 内核的 cuDNN 后端扩展和数据路径性能优化也较活跃。

**最活跃领域**：1. 动态推理与状态管理；2. 训练启动校验与配置；3. MFSDP/FSDP 运行时；4. SSM/稀疏注意力内核；5. 数据与性能优化

## 重点进展
- **GTP SwiGLU checkpoint 顺序修复**：修正 GTP 权重切片下 gate/up 半区被错误映射到 checkpoint 区域的问题，避免 SwiGLU 权重加载错位。[#9265](https://github.com/nvidia/megatron-lm/pull/9265)
- **修复 wide-residual 旧 checkpoint 加载**：检测并映射旧版 `residual_connection` 键，使 #8424 之前的 wide-residual checkpoint 可用于推理加载。[#9334](https://github.com/nvidia/megatron-lm/pull/9334)
- **GTP 优化器 checkpoint 参数身份保留**：在 native-FP8 权重去量化后保留原始参数 identity，修复 `fully_reshardable` 优化器 checkpoint 匹配失败。[#9343](https://github.com/nvidia/megatron-lm/pull/9343)
- **FSDP forced param sync 修复**：`force_sync=True` 现在只 gather forward hooks 实际需要的权重，避免全模型常驻内存及 HFSDP 下的陈旧权重切片。[#9368](https://github.com/nvidia/megatron-lm/pull/9368)
- **推理 eager prefill padding 边界修复**：限制 eager prefill padding 在动态上下文 token buffer 容量内，并拒绝无法按 TP 分割的容量，防止静默截断与后续 assertion 失败。[#9394](https://github.com/nvidia/megatron-lm/pull/9394)
